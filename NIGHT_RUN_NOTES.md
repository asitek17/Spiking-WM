## Что было сделано перед запуском

### 1. OOM с batch_size=32
Первый тест (`batch_size=32, train_ratio=1024`) упал с `torch.OutOfMemoryError` —
модель занимала 21.8 GB из 23.6 GB, не хватило 256 MB для очередного шага.

**Фикс:** `batch_size: 16`, `train_ratio: 512` в обоих конфигах.
Частота обучения не изменилась: `Every(batch_size × batch_length / train_ratio) = Every(2)`.

### 2. Замеры скорости

Серия тестов была ошибочно медленной по двум причинам:
- `--steps 2000` не означает «2000 шагов и стоп» — цикл while всё равно гоняет полные
  `eval_every=10000` итерации, реальный тест занимал 40–60 минут.
- `eval_every=1000` в тестах перегружал eval-фазой (50% времени на инференс без backprop).

**Реальный fps:** 4.2 env-шагов/сек — получен из overnight-лога на шаге [125000].

### 3. Ночной запуск

Запущен оригинальный конфиг (`steps=500000, batch_size=32`), а не изменённый,
потому что `run_night.sh` на сервере использовал файлы из `~/projects/Spiking-WM`,
а не из локальной директории. Тем не менее OOM не случился — при чистом старте
(без конкурирующих процессов) 32-й батч влезает в 24 GB.
